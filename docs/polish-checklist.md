# Browser polish acceptance ledger

Scope: preserve the existing fork and native, RAM-conscious architecture. Verification uses synthetic profiles, a temporary Facet store, local HTML, and in-process provider responses—not real browser profiles or credentials.

## Verified

- Import: committed SQLite WAL history is included without modifying source database/WAL bytes; uncommitted rows are excluded; nested bookmarks deduplicate and omit non-web URLs; Chrome, Firefox, and Safari history timestamps parse correctly; repeated merges do not inflate visit counts; huge counts cannot trap integer conversion; partial failures warn and total failures throw. Asynchronous completion returns on the main thread.
- Import integration (code inspection): custom-profile menu indices come from the rebuilt source list; custom selections survive refresh; refresh and duplicate import actions are guarded while importing. SQLite linkage is present in both build scripts.
- Assistant: both OpenAI and Anthropic loops handle cancellation, concurrent-run rejection, restart after Stop, denied/late approvals, multi-turn in-memory context, visual fallback registration, and API errors. Approval scopes include Allow Once, per-site safe actions, safe actions for the task, and task-scoped YOLO; YOLO resets before the next task. Missing approval UI fails closed.
- Assistant UI: the real native in-browser sidebar is exercised; Run becomes Stop while working, prompt/Clear are disabled and restored, Clear removes model conversation context, and hiding the sidebar cancels active work.
- Browser: address resolution handles localhost, IPv4/IPv6, ports, queries/fragments, and search fallback. Multi-window sessions persist/restore with backward migration from the original single-window format. Agent URLs exclude local files and embedded credentials. Provider endpoints reject remote plaintext HTTP and malformed credential-bearing URLs.
- WebKit privacy: private titles do not update normal history; private favicons do not use the persistent shared URLSession cache; password/OTP/payment field values are absent from snapshots while ordinary input values remain available. Already-cancelled snapshots never wake a sleeping tab.

- Chrome parity (`tools/browser-feature-tests.swift`, loopback server and real WebKit): binary and `Content-Disposition: attachment` responses download intact to the target folder, are quarantined, and never show an error page. A cancelled HTTP Basic sign-in shows the site's 401 page, and signing in loads the page. A dropped connection shows an error page naming the host, and Reload retries the real address. Per-site zoom applies on commit. Page scripts cannot see the isolated bridge handler, while hover and context-menu targets still arrive. The context menu replaces Open Link in New Window with New Tab/Window items and keeps WebKit's other items. The agent fills `<select>` by visible text. A SIGKILLed background renderer stays asleep. Link-opened tabs land after their opener, pinned and unpinned tabs keep their sections, and closing a page's last child returns to the opener.
- Pure logic: download policy and filename sanitizing, benign-error classification, error-page escaping, site-settings persistence, 32px favicon bounding, omnibox inline completion and ranking (case-preserving, www-insensitive, no completion for single visits or phrases), Switch to Tab without duplicate history rows, history deletion and time-ranged clearing, bookmark rename/delete notifications, pinned-tab session round trip, `go_back` approval, Anthropic cache breakpoints on the outgoing copy only, and Markdown rendering.
- Offscreen render check: tab favicons draw upright, the bookmarks bar and new-tab tiles draw icons, and typing `gi` completes to `github.com` with the remainder selected and a four-row dropdown whose first row is highlighted. The app bundle launches against a throwaway `FACET_PROFILE_DIR`.
- History and session: a history full of repeat visits (as after an import) still records a new visit, stays capped, and keeps a frequently visited older site. Quitting with every normal window closed keeps the session the last window saved.
- Agent approval scope (agent parked in the app, code still tested): after **Allow Safe Actions This Task**, navigating within an approved site does not ask, while opening a new site and clicking a non-link element do.
- Blocking (`blockingWebKit`, loopback server and real WebKit): a path rule blocks a subresource; a per-site exception lets it through after a recompile and live rule swap; removing the exception blocks again; switching blocking off really detaches the rules; only the latest compiled list stays in the rule-list store. Exceptions persist, cover subdomains, and match whole domains only. The blocklist parser accepts plain domains, paths, and hosts-file lines.
- Icon: `tools/make_icon.swift` output has transparent corners, an opaque tile on the 824/1024 macOS grid, and no white fringe from the artwork's backdrop (numeric check of the 512 px representation).
- Chrome parity, second batch (`tools/browser-parity-tests.swift`, loopback server and real WebKit): each live tab reports its own WebKit process and memory; the Task Manager lists the browser, every tab and the shared helpers, and Sleep Tab frees a background tab's process; tab hover text shows the site and memory. Search Tabs matches title and address prefixes, requires every word, lists by recent use, switches to the chosen tab and never wakes sleeping tabs. Page info describes the connection, lists and resets one site's remembered permissions, and clearing a site's data leaves other sites' cookies. A tab dropped on another window's strip moves there with its live page. Closed tabs and windows are recorded (never private ones), capped at 25, and reopen in place or as a window with their tabs. Paste and Go sits after Paste, joins an address split across lines, and uses a private pasteboard in tests.
- Idle footprint with one empty tab is unchanged by this batch: about 27 MB for both the previous commit and this build, measured alternately with `tools/kmem` against throwaway profiles.
- Bookmark folders (`tools/bookmark-tests.swift`): the old flat file migrates onto the bar in order with its dates; the tree, ids and last-used folder survive a reload; the flat list follows tree order and lists a page bookmarked twice once; new bookmarks go to the last folder chosen, or the bar once it is deleted; moves reorder, nest, and refuse moving a top-level folder, a folder into itself, or anything into a bookmark; deleting a folder deletes its contents; Bookmark All Tabs saves one folder. Imports keep Chrome roots and nested folders (with dates), Firefox's parent chain (skipping tags), and Safari's Favorites, menu and Reading List, merge folders by name, and stay idempotent. Folder menus fill only when opened; the bar shows folders; the ⌘D bubble renames, files and remembers the folder once, and Remove deletes; the manager opens with top-level folders expanded, keeps open folders across reloads, flattens search results, lands drops after a bookmark, and refuses dropping a folder into itself; Open All wakes only the first tab. Writes are deferred half a second and flushed at quit.
- Scale: 20,000 imported bookmarks in 200 folders import in about 0.4 s, re-import in 0.02 s, take 9 ms per edit, and add about 8 MB to idle memory; idle with no bookmarks is unchanged at about 27 MB.
- Sign-ins from other browsers (`tools/session-import-tests.swift`, synthetic profiles only): each Chromium browser maps to its own Keychain item and hand-picked folders are recognised by location; a missing item fails without a prompt and names that item; a Brave profile decrypts with Brave's key through Chrome's validation. Firefox cookies import with flags and SameSite, accept second and millisecond expiries, and skip container and expired rows without leaking values. Safari's binary cookie file parses with flags, skips damaged and expired records, refuses non-cookie files, is never touched during detection, and points to Full Disk Access when unreadable. The first-launch offer appears once, only for empty profiles, never for throwaway profiles (unless forced), suggests the default browser's most recent profile, ticks only what the browser has, explains the permission macOS will ask for, and imports exactly what was ticked.
- Idle footprint is unchanged (about 27 MB, three alternating runs against the previous commit). A launch with the offer forced on stays up and records that it was offered.
- Passwords (`tools/password-tests.swift`, in-memory store and real WebKit; the Keychain is never touched): host keying shares www and separates other subdomains; save/update/ignore decisions are correct; imported logins are idempotent and newer-wins; the manager list carries no passwords; "never for this site" persists. The Chromium importer decrypts a Login Data password and skips blacklisted, empty, app-bound (v20) and non-web entries without leaking values; Firefox and Safari are refused. End to end: a saved login autofills into a real page's form, and a submit with changed values is captured from the isolated world and would be offered for saving. Reveal/copy go through macOS authentication; private windows never save or autofill.

## Remaining manual checks / boundaries

- Import picker with real user profile permissions, selecting the same custom profile repeatedly, and pane switches during an import. A disposable real Chrome 152 profile is covered separately by `tools/chrome-compat-smoke.sh`.
- Manual real-page verification of the approval sheets (including YOLO warning), stale-ref recovery, screenshot vision fallback, and sleeping-page lease cleanup under sustained browsing/memory pressure.
- Live API-key/OAuth provider compatibility, provider-specific model availability, and Safari Full Disk Access. No live credentials were used.
- Sign-in import was verified against synthetic Chromium, Firefox and Safari files, not real profiles: no real browser's cookies were read. Keychain item names for Brave, Edge, Arc, Vivaldi, Opera and Chromium follow those browsers' published conventions and have not been exercised against installed copies.
- Password import was verified with a synthetic Login Data database, not a real browser's. The reveal/copy authentication, the Keychain-backed store on a real Mac, and autofill against real-world sign-in forms (which vary widely) remain manual checks.
- Stop prevents further actions but does not undo completed actions or cancel account-level OAuth flows. Page text can still contain sensitive information; field-value redaction is not a general-purpose data-loss-prevention system.
- Provider-native token streaming is not implemented yet; final provider text is currently delivered incrementally to the sidebar after the JSON response completes.
- Not automated (needs Accessibility permission for synthetic input): the real file-upload panel, print panel, press-and-hold Back menu, dragging pinned tabs, the omnibox's arrow keys and Escape, and the downloads popover. The audio indicator depends on WebKit's `_isPlayingAudio` KVO and the mute on `_setPageMuted:`, both SPI, guarded by `responds(to:)`, with a JavaScript fallback for mute. The shield's per-site menu is covered at the rule and WebKit level, not by clicking the menu. Also not automated: the tab drag gesture itself (the drop logic is tested), clicks on the lock and shield menus, and File → Share. Also not automated: clicking a bar folder, the star opening the bubble, and dragging rows in the bookmark manager (the drop logic is tested).
